What the model actually learns

Sequence surprise / 50%

A first-order Markov model learns event-to-event transition counts with additive smoothing. Unfamiliar order raises average transition surprise.

Volume & pace / 40%

Log session length and mean log inter-event gaps are compared with the baseline mean and spread. Single-event sessions have no pace evidence.

Start hour / 10%

The learned frequency of session starts by UTC hour. It cannot infer anyone's work schedule or location.

Input contract, privacy & known blind spots

JSONL fields: timestamp (ISO 8601 with seconds and timezone), session (string), event (string). Extra fields are ignored. Use pseudonymous session IDs; do not paste credentials, personal data or real incident logs without permission. Each input is limited to 5,000 events and 1.5 million characters. Malformed inputs are rejected rather than silently skipped.

Nothing is saved by this app: no cookies, analytics, local storage, remote model or inference request. Your host still receives ordinary page requests and connection metadata. Export is opt-in and includes session IDs; protect that file.

Sessions use your explicit ID, with no automatic timeout splitting. Reusing an ID across days merges those events. Training contamination, short baselines, event-schema changes and legitimate new workflows can mislead the model. First-order transitions lose long-range context. No geography or impossible-travel claim is made.

The demo's "known-blind-spot" has the same observed pattern as a normal retry, but could represent a patient malicious login. It should score low. Intent is not in these fields. Try changing the new export events to a legitimate new workflow: it will still flag novelty.
